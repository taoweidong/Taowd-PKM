# 前端工程化与模块化

> [!摘要] 摘要
> 本文是「前端工程化与模块化」知识点的落地学习文档，回答三个问题：**前端如何组织代码（模块化规范）**、**如何把源码变成可上线的产物（构建工具链）**、**如何让工程能力服务真实项目（工程化实践）**。内容以当前主流 **ES Modules + Vite 8 / Rolldown** 为主线，覆盖 ESM 与 CommonJS 的差异、Tree Shaking 的生效条件、Vite 8 的 Rust 化构建架构、代码分割与库模式，以及 dual-package hazard、依赖治理等高频坑点。定位为 [[Vue3与前端-从入门到精通]] 体系下的工程底座篇，适合在掌握语言基础后、进入生产项目前阅读。

## 一、最新动态（截至 2026-11）

- **构建工具 Rust 化收敛**：**Vite 8.0**（2026-03-12 发布）用 **Rolldown**（基于 Rust）取代了「esbuild（开发）+ Rollup（生产）」的双打包器，配合 **Oxc**（解析/转译/压缩）与 **Lightning CSS**（CSS 压缩），官方称构建提速 **10–30×**，并对 Rollup 插件 API 保持兼容。Vite 8 要求 **Node.js 20.19+ / 22.12+**，以 **ESM-only** 包分发；安装体积相比 Vite 7 约增加 **15 MB**。
- **模块规范以 ESM 为绝对主流**：现代项目默认 ESM（`export` / `import`，静态分析支持 Tree Shaking）；CommonJS 同步加载、输出值拷贝，仅在存量项目与部分服务端场景存在；AMD / UMD / IIFE 属历史方案。
- **Node 对 ESM 的支持已成熟**：Node 默认支持 `require(esm)`，这是 Vite 8 依赖的基础能力，也让 ESM 与 CJS 混用时的互操作成本进一步降低。
- **语言与工具链升级**：**TypeScript 7.0（Go 原生移植）于 2026-07-08 GA**，官方称约 10× 提速，但**不再提供 JS 端编译器 API**；5.x 最新为 **5.9.3**。前端工程化向「端到端同源工具链（Oxc / Rolldown / Lightning CSS）」收敛。
- **测试与元框架配套**：Vitest 发布 **5.0**（2026-09-03，5.1 于 2026-11-01），要求 **Vite ≥ 6.4.0、Node ≥ 22.12.0**；Nuxt **4.6.0**（2026-10-05）默认由 Nitro 驱动。
- **来源**：[Vite 8 发布博客](https://vite.dev/blog/announcing-vite8.html)、[MDN · ES Modules](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Modules)、[TypeScript 官方博客](https://devblogs.microsoft.com/typescript/)

## 二、基础概念

**模块化**是把代码按功能/边界拆分为可独立维护、独立复用的单元，并定义单元之间「如何引用、如何导出」的规范；**工程化**则是在此基础上，用工具链统一处理开发、构建、测试、交付与依赖治理，让项目可规模、可协作、可重复构建。

前端历史演进：从 `<script>` 标签全局变量，到 AMD/UMD/IIFE 的社区方案，再到 **ESM** 成为浏览器与 Node 共同标准，模块规范之争基本结束。各规范的关键差异：

| 规范 | 语法 | 加载方式 | 特点与现状 |
| --- | --- | --- | --- |
| **ESM** | `export` / `import` | 异步、静态分析 | 标准；支持 Tree Shaking、动态导入，现代项目默认 |
| **CommonJS** | `module.exports` / `require` | 同步 | 输出值拷贝、运行时求值；存量项目与服务端常见 |
| **AMD** | `define` / `require[]` | 异步（浏览器） | RequireJS 时代方案，已基本淘汰 |
| **UMD** | 兼容 CJS/AMD/全局 | 混合 | 跨环境发布库时的历史方案 |
| **IIFE** | 立即执行函数 | 传统 `<script>` | 全局命名空间方式，仅遗留代码 |

**构建工具**在工程化中承担核心职责：开发期提供快速启动、HMR 与原生 ESM 服务；生产期完成打包、转译、压缩、代码分割、Tree Shaking、Source Map 与资源优化。当前主流是 **Vite**（通用应用）、**Rollup**（发布精简库）、**Webpack**（深度定制的复杂组件库）。

## 三、核心机制

**1. ESM 的静态分析与 Tree Shaking。** ESM 的 `import` / `export` 是静态声明，构建器在打包前就能建立完整模块依赖图，从而：
- **Tree Shaking**：剔除未被引用的导出，只保留真正使用的代码（副作用代码需用 `sideEffects` 字段声明，否则可能被保留）；
- **代码分割（Code Splitting）**：结合动态 `import()`，将路由、重组件拆成独立 chunk，按需加载。

**2. Vite 8 的双阶段架构。** 开发期仍走**原生 ESM**——浏览器直接请求源文件，Vite 用 Rolldown 做**依赖预打包**（把依赖转成浏览器可消费的 ESM），从而保留极速冷启动与毫秒级 HMR；生产期则由 **Rolldown 作为唯一打包器**统一完成打包与压缩，取代过去「开发 esbuild + 生产 Rollup」的双打包器，插件兼容 Rollup API，多数现有 Vite 插件可直接工作。转译压缩链路为：**Oxc**（解析/转译/压缩）+ **Lightning CSS**（CSS 压缩）。

**3. 包管理与模块格式。** 现代包以 pnpm/npm 管理，`package.json` 的 `type` 字段决定 `.js` 被解释为 ESM 还是 CJS；**发布单一模块格式（CJS 或 ESM）通常更佳**，因为同时暴露两种格式、又没有正确互操作时，可能导致**同一包出现两份实例**，引发 `instanceof` 判断失败、响应式/单例状态不一致等隐蔽问题（即 dual-package hazard）。

**4. 运行时模块组合。** 大型应用可借助 **Module Federation**（Webpack / Rolldown 支持）在运行时从远端容器动态加载模块，容器接口支持 `get` / `init`，`init` 为异步调用并兼容单参共享 scope 对象，用于把远端容器接入宿主，实现独立部署与依赖共享。

## 四、实践步骤（含代码/命令示例）

**1. 环境与脚手架。** 先核对 Node 版本（Vite 8 要求 Node 20.19+ / 22.12+）：

```bash
node -v        # 应为 20.19+ / 22.12+ 或更高
pnpm -v
```

用官方脚手架创建基于 Vite 的项目：

```bash
pnpm create vite@latest my-app -- --template vue-ts
cd my-app
pnpm install
pnpm run dev    # 开发服务器，默认 http://localhost:5173
pnpm run build  # 生产构建
pnpm run preview
```

**2. 声明 ESM 与路径别名。** 在 `package.json` 中把包标记为 ESM（Vite 8 本身即 ESM-only）：

```json
{
  "name": "my-app",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build"
  }
}
```

**3. 配置 Vite。** 典型配置，覆盖别名、构建分块与模块联邦宿主：

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { fileURLToPath, URL } from 'node:url'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          vue: ['vue', 'vue-router', 'pinia'],
        },
      },
    },
  },
})
```

**4. 代码分割与动态导入。** 用动态 `import()` 实现按需加载：

```typescript
// 路由级懒加载：只有进入该路由时才加载对应 chunk
const routes = [
  { path: '/dashboard', component: () => import('@/views/Dashboard.vue') },
]
```

**5. 库模式发布。** 用 Vite 的库模式（底层 Rollup）产出精简的 ESM/CJS 产物：

```typescript
// vite.lib.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  build: {
    lib: {
      entry: 'src/index.ts',
      name: 'MyLib',
      formats: ['es', 'cjs'],
      fileName: (format) => `my-lib.${format}.js`,
    },
    rollupOptions: {
      external: ['react', 'react-dom'],
    },
  },
})
```

```bash
vite build --config vite.lib.config.ts
```

## 五、最佳实践与常见坑

- **统一模块格式**：新库优先只发布 **ESM**（必要时提供 CJS 适配），避免 dual-package hazard；若必须双格式，用正确的 interop 保证单实例。
- **锁定依赖 minor**：对 `vue` 等类型定义可能在小版本间不兼容的包，采用锁定 minor 的 semver 范围，升级时手动确认。
- **让 Tree Shaking 真正生效**：库的 `package.json` 声明 `"sideEffects": false`（或明确列出有副作用的文件）；避免在模块顶层写有副作用的全局操作；避免用 `export default` 单一对象包所有能力。
- **合理分块**：用 `manualChunks` 把框架等稳定依赖单独分块，避免业务代码改动导致框架重复下载；但不要为了拆分而制造过多小 chunk，反而增加请求数。
- **Vite 8 迁移**：内置兼容层会自动把 `esbuild` / `rollupOptions` 配置转换为 Rolldown / Oxc 等价物，多数项目无需改配置；大项目建议先在 Vite 7 上切 `rolldown-vite` 验证，再升级 Vite 8，并留意约 **15 MB** 的安装体积增加。
- **TS 7 工具链验证**：TS 7 无 JS 编译器 API，依赖 `ts.*` 的工具链（Volar / vue-tsc 路线等）需先验证兼容性，必要时使用 `@typescript/typescript6` 兼容包装或回退 TS 5.x。
- **产物可观测**：构建后做产物分析，检查 chunk 拆分、重复依赖、Source Map 与体积预算，防止页面载荷持续膨胀。

## 六、核心要点速查

1. **ESM 是现代前端模块标准**：静态分析、支持 Tree Shaking 与动态导入；CJS 同步、输出值拷贝。
2. **前端工程化 = 模块化 + 构建工具链 + 依赖治理**，目标是可规模、可协作、可重复构建。
3. **Vite 8.0（2026-03-12）** 以 **Rolldown** 取代 esbuild + Rollup 双打包器，官方称构建提速 **10–30×**。
4. **转译压缩链**：**Oxc**（解析/转译/压缩）+ **Lightning CSS**（CSS 压缩）。
5. **Node 要求**：Vite 8 需 **Node 20.19+ / 22.12+**，Vite 8 为 **ESM-only**，依赖 `require(esm)`。
6. **Tree Shaking 条件**：静态 `import/export` + 正确声明 `sideEffects`。
7. **代码分割**：动态 `import()` + 路由懒加载，配合 `manualChunks` 分块。
8. **避免 dual-package hazard**：优先发布**单一模块格式**，防止同一包出现两份实例。
9. **库发布**：Vite/Rollup **库模式**产出 ESM/CJS 精简产物。
10. **运行时组合**：大型应用可用 **Module Federation**（Webpack / Rolldown）动态加载远端容器。
11. **测试配套**：Vitest 5 要求 **Vite ≥ 6.4.0、Node ≥ 22.12.0**。
12. **语言基座**：TypeScript 7.0（2026-07-08 GA）为 Go 原生移植，**无 JS 编译器 API**。
