## 二、文档统一结构（每篇）

```
frontmatter（title/date/updated/tags/aliases/source）
→ # 标题
→ > [!summary] 摘要
→ 一、最新动态（截至 2026-11，仅写来源可确认内容）
→ 二、入门篇（基础概念 / 环境准备 / 第一个实践）
→ 三、进阶篇（核心机制 / 最佳实践 / 常见问题与排查）
→ 四、精通篇（架构设计 / 生产实践 / 生态与前沿）
→ 五、核心要点速查
→ 六、学习资源（外部官方链接）
→ 七、关联笔记（wikilink）
→ 八、变更记录
```

## 三、执行阶段（多 agent 并行）

| 阶段 | 动作 | 方式 |
|------|------|------|
| 阶段 0 | 规划与目录确认 | 主 agent 完成（本文件） |
| 阶段 1 | 6 主题并行**调研**：web_search + 官方文档/权威来源，抽取版本、入门到精通路径、核心要点 | 6 个调研 agent 并行 |
| 阶段 2 | 6 主题并行**写作**：按统一结构写入指定 md，仅写各自文件 | 6 个写作 agent 并行 |
| 阶段 3 | **交叉审校**：事实/版本准确性、Obsidian 规范、无占位、链接有效 | 3 个审校 agent，每人 2 篇，直接修正 |
| 阶段 4 | **集成**：更新主结构索引（`40-AI技术.md`、`前端开发.md`、`DevOps.md`、`编程语言.md`、`标签索引.md`、`20-技术积累.md`、`最近更新.md`） | 主 agent |
| 阶段 5 | 汇总交付与核对 | 主 agent |

## 四、质量红线

- **事实准确**：版本号、功能、变更必须来自调研来源，不编造；不确定处写「以官方文档为准」。
- **引用来源**：外部资料用 Markdown 链接，文末列出。
- **Obsidian 规范**：frontmatter、wikilink、callout、嵌套标签，遵守 [[obsidian-markdown]]。
- **写入隔离**：各 agent 只写自己被分配的文件，不改动 `wiki-system/raw/`、他人文件与索引文件（索引由主 agent 统一更新）。
- **中文输出**，代码块注明语言。
