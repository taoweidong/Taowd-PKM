### 1\. 数据库事务核心基础（ACID）

事务是数据库**最小执行单元** ，是一组 SQL 的批量执行逻辑，要么全部成功，要么全部失败回滚。事务的诞生，是为了解决并发读写带来的数据不一致问题。

事务拥有四大经典特性，也就是面试必背的 **ACID** 。

#### 1.1 A 原子性（Atomicity）

最小执行单元，**事务不可拆分** 。一组 SQL 要么全部执行成功、整体提交；要么任意一步失败，全部回滚，不会出现部分成功、部分失败的中间状态。

**底层依赖** ：undo log 回滚日志。出错时依靠 undo log 恢复数据，保证原子性。

#### 1.2 C 一致性（Consistency）

数据库从一个合法一致性状态，变换到另一个合法一致性状态。事务执行前后，数据约束、业务规则、完整性不被破坏。

例如转账场景：A 减钱、B 加钱，总金额不变，不会出现资金凭空增加或消失的问题。

**注意** ：一致性是最终目的，原子性、隔离性、持久性都是为了保障一致性。

#### 1.3 I 隔离性（Isolation）

多个事务并发执行时，事务之间相互隔离、互不干扰。隔离性是**并发事务最核心的难点** ，也是 MVCC 存在的意义。

数据库为了平衡性能与一致性，提供了四种隔离级别，隔离级别越高，一致性越强、性能越差；隔离级别越低，并发越高、问题越多。

#### 1.4 D 持久性（Durability）

事务一旦提交成功，数据永久落地，即使断电、宕机、重启，数据也不会丢失。

**底层依赖** ：redo log 重做日志。提交前写入 redo log，宕机重启后通过日志恢复数据，保证持久化。

### 2\. 并发事务三大问题（脏读、不可重复读、幻读）

如果事务完全不隔离，并发执行会出现三种数据一致性问题，严重破坏业务逻辑。这三个问题是理解隔离级别的前提，必须精准区分。

#### 2.1 脏读（Dirty Read）

**定义** ：一个事务读取到了**另一个事务未提交的脏数据** 。

**场景** ：事务B 修改数据未提交，事务A 读取到了未提交的数据，随后事务B 回滚，导致A读到的数据是无效脏数据。

**危害极大** ：读到不存在的数据，直接导致业务错乱、统计错误、资金异常。

#### 2.2 不可重复读（Unrepeatable Read）

**定义** ：**同一个事务内，两次读取同一条数据，结果不一致** 。

**场景** ：事务A 开启、查询一次数据，事务B 修改并提交该数据，事务A 再次查询，数据发生变化。

**侧重点** ：针对**单条数据** 的修改更新。

#### 2.3 幻读（Phantom Read）

**定义** ：**同一个事务内，两次范围查询，条数不一致** 。

**场景** ：事务A 范围查询多条数据，事务B 插入/删除一条数据并提交，事务A 再次查询发现多了/少了数据，像产生幻觉一样。

**侧重点** ：针对**数据新增、删除、范围条数** 变化。

#### 2.4 三者面试满分区别

脏读：读了别人**未提交** 的数据（最严重）；

不可重复读：别人**更新** 单条，导致自己前后不一致；

幻读：别人**增删** 数据，导致自己前后条数不一致。

### 3\. 四大隔离级别详解（MySQL 默认 RR）

SQL 标准定义了四大隔离级别，从上到下隔离性越来越强、性能越来越差、问题越来越少。

#### 3.1 读未提交（Read Uncommitted）

最低级别，可读取其他事务未提交数据。

**问题** ：脏读、不可重复读、幻读全部存在。

**使用场景** ：业务几乎不用。

#### 3.2 读已提交（Read Committed / RC）

只能读取其他事务**已经提交** 的数据。

**解决** ：彻底解决脏读。

**遗留问题** ：不可重复读、幻读依然存在。

**特点** ：每次读取都会生成最新快照，数据实时性高。

#### 3.3 可重复读（Repeatable Read / RR）

**MySQL InnoDB 默认隔离级别** 。

**解决** ：脏读、不可重复读彻底解决。

**遗留问题** ：**普通 MVCC 下存在幻读，锁机制下可以解决幻读** 。

**特点** ：事务开启后，读取快照固定，保证同事务内重复读取数据一致。

#### 3.4 串行化（Serializable）

最高隔离级别，事务串行执行，完全杜绝并发问题。

**解决** ：脏读、不可重复读、幻读全部解决。

**缺点** ：并发性能极差，完全不适合高并发业务。

### 4\. 快照读与当前读（MVCC 核心前置）

很多人看不懂 MVCC，根源是分不清**快照读** 和**当前读** 。

#### 4.1 快照读（普通 select）

普通不加锁的 select 查询，读取的是**历史快照版本数据** ，不加锁、无阻塞、高并发，依靠 MVCC 多版本控制实现。

**优势** ：读写不冲突，极大提升并发性能。

#### 4.2 当前读（加锁读写）

读取数据库**最新实时数据** ，会加行锁，阻塞其他事务修改。

包含：insert、update、delete、select ... for update、lock in share mode。

#### 4.3 核心结论

**MVCC 只作用于快照读，当前读走锁机制** 。

### 5\. MVCC 多版本并发控制（全文最难核心）

**MVCC（Multi-Version Concurrency Control）多版本并发控制** ，是 InnoDB 实现高并发、读写不阻塞的核心机制。

核心思想：**数据保留多个历史版本，不同事务读取不同版本，实现读写并行、互不阻塞** 。

没有 MVCC，数据库读写互斥、并发极低；有了 MVCC，**读不加锁、读写不冲突** ，支撑高并发业务。

#### 5.1 MVCC 三大支撑要素

1\. **隐藏字段** ：每条记录自带 DB_TRX_ID、DB_ROLL_PTR、DB_ROW_ID

2\. **undo log** ：保存数据修改前的历史版本，形成版本链

3\. **read view** ：读视图，版本筛选规则

#### 5.2 三条隐藏字段详解

**DB_TRX_ID** ：最后修改这条数据的事务ID

**DB_ROLL_PTR** ：回滚指针，指向 undo log 上一条历史版本

**DB_ROW_ID** ：行唯一ID（无主键时用作聚簇索引）

#### 5.3 undo log 版本链

每次数据更新，不会直接覆盖旧数据，而是将旧数据存入 undo log，通过 roll_ptr 指针串联成一条**历史版本链表** 。

一条数据可以存在多个历史版本，不同事务根据规则读取对应版本，这就是多版本的由来。

#### 5.4 Read View 读视图（筛选规则）

read view 是事务读取数据时的**判断规则** ，核心四个字段：

1\. m_ids：当前活跃未提交事务ID集合

2\. min_trx_id：m_ids 最小事务ID

3\. max_trx_id：m_ids 最大事务ID

4\. creator_trx_id：当前事务自身ID

**判断逻辑** ：遍历版本链，找到第一条满足可见性规则的版本，作为当前事务读取结果。

### 6\. RC 与 RR 隔离级别底层差异（面试深挖）

MVCC 在 RC 和 RR 下的行为完全不同，本质差异在于 **read view 生成时机不同** 。

#### 6.1 RC 读已提交

**每次 select 都会生成新 read view** 。

每次读取都是最新视图，能读到其他事务刚提交的数据，所以**无法解决不可重复读** 。

#### 6.2 RR 可重复读（MySQL 默认）

**事务内第一次 select 时生成 read view，后续复用** 。

整个事务视图固定，读取的都是同一个快照，所以**解决了不可重复读** 。

### 7\. 终极问题：RR 到底有没有解决幻读？

这是面试**绝杀题** ，90% 的人答不完整。

**标准答案：**

1\. **纯 MVCC 快照读下** ：RR 通过固定快照，避免了幻读现象，事务内数据始终一致；

2\. **当前读加锁场景下** ：MVCC 无效，依靠 **Next-Key Lock 临键锁** 锁住区间，彻底杜绝幻读；

3\. **总结** ：MySQL RR 级别**彻底解决了幻读问题** ，这也是 MySQL 放弃通用标准、坚持默认 RR 的核心原因。

### 8\. 高频面试真题·满分标准答案

**Q1：简述事务ACID四大特性？** 答：A原子性：事务整体不可拆分，要么全成功要么全回滚；C一致性：事务前后数据合法一致；I隔离性：并发事务相互隔离不干扰；D持久性：提交后数据永久落地，宕机不丢失。

**Q2：脏读、不可重复读、幻读区别？** 答：脏读是读取到未提交脏数据；不可重复读是同一事务两次查单条数据结果不同（他人更新）；幻读是同一事务两次范围查询条数不同（他人增删）。

**Q3：MVCC原理是什么？作用是什么？** 答：MVCC即多版本并发控制，通过undo log保存数据历史版本，结合read view读视图规则，让不同事务读取对应历史快照，实现**读不加锁、读写不阻塞** ，极大提升数据库并发能力，是RC、RR隔离级别的核心实现。

**Q4：RC和RR的底层区别？** 答：核心是read view生成时机不同。RC每次查询都生成新视图，实时性高，存在不可重复读；RR首次查询生成视图并复用，事务内快照固定，解决不可重复读。

**Q5：MySQL默认隔离级别为什么是RR？** 答：RR解决脏读、不可重复读，配合临键锁彻底解决幻读；兼顾了数据一致性与高并发性能，比RC更稳定，比串行化性能更高，是综合最优方案。
