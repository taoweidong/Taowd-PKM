## 二、基础概念

**嵌入模型（Embedding Model）**：把文本、图像等离散数据映射为**固定维度的稠密向量**（如 1536 维、3072 维）。映射的核心性质是**语义相近 → 向量距离近**，从而把「语义匹配」转化为「向量空间中的近邻搜索」。

**向量数据库（Vector Database）**：专门用于存储、索引并高效检索高维向量的数据库。相比传统关系库，它的核心能力不是精确匹配，而是**近似最近邻（ANN, Approximate Nearest Neighbor）**——在可接受的精度损失下大幅提速，支撑百万到百亿级向量的毫秒级检索。

**关键概念**：

| 概念 | 说明 |
| --- | --- |
| 向量维度 | 由嵌入模型决定（如 1536/3072），维度越高信息越丰富，但索引与存储成本越高 |
| 距离度量 | 余弦相似度（最常用）、欧氏距离、内积；需与模型归一化策略一致 |
| 索引结构 | HNSW（内存型、召回高）、IVF-PQ（磁盘/压缩、可扩展）、标量倒排过滤 |
| 标量过滤 | 先按普通字段（时间、标签、分类）过滤，再做向量检索 |
| 混合检索 | 向量检索 + BM25 关键词检索互补，提升精确匹配与召回 |
| 重排（Rerank） | 用交叉编码器等模型对召回结果二次精排，提升精度 |

> [!note] 体系定位
> 在 RAG 的五步流水线「切分 → 向量化 → 索引 → 检索 → 生成」中，本知识点覆盖的是**向量化、索引、检索**三环，检索质量直接决定生成质量。详见 [[RAG检索增强生成]]。

## 三、核心机制

**1. 嵌入模型如何产出向量**：文本先经分词（tokenizer）切成 token，再送入 Transformer 编码器，经过多层自注意力聚合上下文语义，最后通过**池化（如取 [CLS] 或均值池化）+ 归一化**得到定长向量。归一化后可直接用内积等价于余弦相似度，便于批量计算。

**2. 相似度与距离**：余弦相似度衡量方向一致性，适合语义匹配；欧氏距离衡量空间绝对距离；内积适合归一化后的快速计算。**度量必须与模型训练时一致**，混用会导致召回异常。

**3. 索引与 ANN**：暴力全量比对是 O(n)，无法应对大规模。HNSW 通过分层小世界图实现近邻跳跃，召回高、延迟低，但占用内存；IVF-PQ 通过聚类中心 + 乘积量化压缩，适合海量数据与磁盘/云场景。工程上通常在两者之间做取舍，并配合 `efSearch`、`nprobe` 等参数调节精度与速度。

**4. 混合检索与重排**：向量擅长语义泛化，BM25 擅长精确关键词（型号、人名、术语）。两者结果通过 **RRF（Reciprocal Rank Fusion）** 融合，再由重排模型对 Top-K 精排，往往比单一向量检索更稳。

**5. 更新、删除与一致性**：向量库需要支持按 ID 更新/删除（文档内容变化时重新嵌入），以及事务性、快照或最终一致性，避免检索到过期数据。

## 四、实践步骤（含代码/命令示例）

**步骤 1：选型**。小规模/嵌入式选 LanceDB、pgvector；中等规模选 Qdrant、Weaviate；大规模分布式选 Milvus。区分**内存型 / 磁盘型 / 云托管**，并确认是否支持过滤、混合检索与重排。

**步骤 2：本地嵌入与检索（最小可运行示例）**

```python
# 使用 sentence-transformers 生成向量，并做一次本地近邻检索
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("BAAI/bge-m3")  # 中文场景常用的自托管模型

texts = ["向量数据库用于高维向量检索", "嵌入模型把文本映射为向量", "RAG 用检索增强生成"]
vectors = model.encode(texts, normalize_embeddings=True, convert_to_numpy=True)

query = "向量检索"
qv = model.encode([query], normalize_embeddings=True, convert_to_numpy=True)[0]
scores = vectors @ qv  # 归一化后内积 = 余弦相似度
for text, score in sorted(zip(texts, scores), key=lambda x: -x[1]):
    print(f"{score:.4f}  {text}")
```

**步骤 3：写入 Milvus 并检索（pymilvus）**

```python
from pymilvus import MilvusClient, DataType

client = MilvusClient(uri="http://localhost:19530")
collection = "kb_docs"
client.create_collection(
    collection_name=collection,
    vector_field_name="embedding",
    dimension=1024,          # 与嵌入模型输出维度一致
    primary_field_name="id",
    id_type=DataType.STRING,
    auto_id=False,
    enable_dynamic_field=True,
)
client.insert(collection, [
    {"id": "1", "embedding": vectors[0].tolist(), "content": texts[0]},
])
client.create_index(collection, field_name="embedding", index_type="HNSW")
client.load_collection(collection)

res = client.search(
    collection, data=[qv.tolist()], limit=3,
    output_fields=["content"],
    search_params={"metric_type": "COSINE", "params": {"ef": 64}},
)
print(res)
```

**步骤 5：pgvector（PostgreSQL 生态，适合已有关系库）**

```sql
CREATE EXTENSION vector;
CREATE TABLE docs (id text PRIMARY KEY, content text, embedding vector(1536));
-- 写入后建 HNSW 索引
CREATE INDEX ON docs USING hnsw (embedding vector_cosine_ops);
-- 带标量过滤的向量检索
SELECT id, content, embedding <=> '[...]' AS distance
FROM docs WHERE category = 'ai'
ORDER BY embedding <=> '[...]' LIMIT 5;
```

**步骤 6：调用 OpenAI 嵌入 API**

```python
from openai import OpenAI
client = OpenAI()
resp = client.embeddings.create(
    model="text-embedding-3-small", input=["向量数据库", "嵌入模型"],
)
print([d.embedding[:5] for d in resp.data])  # 1536 维
```

## 五、最佳实践与常见坑

- **维度与模型必须一致**：不同嵌入模型的向量不可混存、不可混查；更换模型意味着全部重新嵌入，务必在 schema 中记录模型名与维度。
- **归一化与度量要匹配**：模型若输出归一化向量，用内积/余弦即可；未归一化时直接用欧氏距离，避免度量与向量不匹配导致召回劣化。
- **中文场景优先中文模型**：BGE-M3、BGE 系列对中文语义建模更稳；多语言通用模型在专业术语上可能不如专用模型。
- **混合检索 + 重排收益明显**：单靠向量检索容易漏掉精确关键词，建议叠加 BM25 与 Rerank，并为核心检索设定独立 SLO（如 p95 延迟、recall@k）。
- **切分粒度要先行**：向量化前先保证文档切分合理，chunk 太长导致语义稀释、太短丢失上下文，向量库也救不回来。
- **不要只做权重量化式优化**：向量库的存储与索引成本与数据规模、维度直接相关，需单独评估容量与内存占用，不能与模型权重量化混为一谈。
- **注意一致性与删除**：源文档更新后要同步重新嵌入并删除旧向量，否则检索到过期内容；生产环境关注最终一致性窗口。
- **按规模与运维成本选型**：嵌入式库上手快但扩展受限；分布式库能力强但需要运维 K8s/存储；云托管省事但引入数据出境与成本问题。
- **避免把向量库当全文检索库**：向量库擅长语义，精确匹配、聚合统计、复杂 SQL 仍是传统库的强项，二者常组合使用。

## 六、核心要点速查

1. 嵌入模型把文本映射为稠密向量，语义相近 → 向量距离近，是语义检索的基石。
2. 向量数据库以 ANN 为核心，用可接受的精度损失换取大规模下的毫秒级检索。
3. 距离度量（余弦/欧氏/内积）必须与模型归一化策略一致，混用会劣化召回。
4. HNSW 召回高、偏内存；IVF-PQ 可压缩、可扩展，二者按数据规模取舍。
5. 混合检索（向量 + BM25）配合 RRF 与重排，通常优于单一向量检索。
6. 维度、模型必须全局一致，换模型等于全量重新嵌入，需在 schema 中固化模型信息。
7. RAG 五步中本知识点覆盖「向量化 → 索引 → 检索」，检索质量决定生成质量。
8. 选型看规模与运维：嵌入式（LanceDB/pgvector）、内存型（Qdrant/Weaviate）、分布式（Milvus）。
9. 中文场景优先 BGE 系等中文模型，专业术语召回更稳。
10. 为检索设定独立 SLO，不要只盯最终回答质量。
