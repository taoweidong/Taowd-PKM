# Obsidian 开发者个人工作台插件 — 设计方案

> [!info] 文档关系
> 本方案基于 [[Obsidian开发者工作台插件-开源调研分析报告]]（两轮调研，11 个首页类 + 6 个外观类 + 8 个工作流类开源项目）。功能点均标注来源插件，汇聚各家已验证的核心能力，不重复造轮子。

**暂定名**：DevDeck / 开发驾驶舱
**一句话定位**：开发者的常驻知识驾驶舱——以"最近编辑 × 标签共现"为核心的侧边栏工作台，科技风遥测界面，一眼读懂 vault 状态。

---

## 一、产品定位与核心场景

**目标人群**：用 Obsidian 管理技术笔记、项目文档、日记的软件开发人员。

**三个核心场景**：

| 场景 | 用户心智 | 工作台响应 |
|------|---------|-----------|
| 回到现场 | "我刚才在写什么？" | 最近编辑列表（mtime 序），一键续写 |
| 按线索导航 | "数据库相关的笔记都有哪些？" | 标签共现导航，点选即交叉过滤 |
| 启动今天 | "今天该干什么？" | 状态条（今日编辑/待办/git）+ 快捷入口 |

**设计目标**（用户原话）：界面炫酷、科技风、内容一目了然。

**市场依据**：11 个竞品无一提供常驻侧边栏；标签共现导航随 dashboard-navigator 下架而绝迹；官方 Bases 不做侧边栏/任务写回/标签共现——垂直组合有明确生存空间。

## 二、功能全景（汇聚开源核心功能点）

优先级：**M1** 核心闭环 / **M2** 完整体验 / **M3** 开发者深化。

| # | 功能 | 具体设计 | 来源插件（许可证） | 优先级 |
|---|------|---------|-------------------|--------|
| F1 | 最近编辑列表 | mtime + 最近打开混排（可切换纯 mtime）；相对时间每分钟刷新；等宽时间列对齐；默认 10 条不滚动；排除文件夹规则 | StartPage（MIT）的混排与刷新机制 | **M1** |
| F2 | 标签共现导航 | 标签面板带计数、按频率排序；点主标签→展开共现次级标签；Shift+点击 AND、Ctrl+点击排除；与 F1 交叉过滤 | dashboard-navigator（MIT，已归档）独门功能 | **M1** |
| F3 | 双形态视图 | 常驻侧边栏速览 + 主区沉浸仪表盘，共享数据层；按**实测宽度**阈值自动单列重排（窄侧栏=单列） | 形态为市场空白；重排机制来自 Hearth（MIT） | **M1** 侧边栏 / **M2** 主区 |
| F4 | 搜索 | 文件名模糊搜索+类型过滤、键盘流（Tab 激活）；进阶：title 属性与文内标题命中直达；结果自解释（H1/命中段落摘录）；可选接 Omnisearch 引擎 | Home tab + Harbor Tab + Home Launcher（均 MIT）；Omnisearch 本库已装 | **M2** |
| F5 | Pin 固定区 | 右键/文件树菜单/长按多入口 pin；拖拽排序；**一键导入核心 Bookmarks**，不自建收藏孤岛 | StartPage/Hearth（MIT）多入口体系 | **M2** |
| F6 | 状态条 + 编辑脉冲 | 顶部一行：今日编辑数、待办数、git 分支状态；近 14 天编辑 sparkline（唯一编排动效）；编辑发生时对应行短暂亮起 | 原创视觉；统计口径参考 daily-activity（MIT） | **M1** 状态条 / **M2** sparkline |
| F7 | 快捷入口 launcher | "按钮即数据"：新建笔记（模板占位符）、快速捕获追加到日记、跑任意命令、开文件/URL；可挂 QuickAdd 宏 | Home Launcher（MIT）；StartPage 模板新建；QuickAdd 本库已装 | **M2** |
| F8 | 皮肤系统 | 默认皮肤消费官方 CSS 变量随主题适配；「驾驶舱」科技风为 class-toggle 预设；全部视觉参数走 Style Settings `@settings`；预设下拉+热键切换；沉浸模式复用 Hider `.hider-*` 契约 | Style Settings（GPL，只用格式不抄代码）+ Minimal Theme Settings + Hider（MIT） | **M1** 基础 / **M2** 预设切换 |
| F9 | 任务聚合 | 侧边栏待办卡：按标签/文件聚合 `- [ ]`，勾选**双向写回**原文件；到期/逾期语义色 | obsidian-tasks + checklist（MIT）范式 | **M3** |
| F10 | Git 状态卡 | 当前分支、未提交变更数、最近提交；点击唤起 obsidian-git 命令；**防御性探测**，未装/升级即降级隐藏 | obsidian-git（MIT，本库已装）；Hearth Git 卡 #464 教训 | **M3** |
| F11 | Tag Wrangler 集成 | 标签右键接入其重命名/合并菜单；Alt+点击标签跳转/创建 Tag Page；监听其公开事件 | Tag Wrangler（ISC，本库已装） | **M2** |
| F12 | 库统计 | 笔记总数、今日编辑、体积；16 周热力图（与 F6 sparkline 二选一或合并，避免重复） | StartPage（MIT） | **M2** |

> [!tip] 取舍原则
> 每个功能点都来自竞品已验证的实现或真实 issue 教训；**没有来源的原创功能只有 F6 的视觉编排**——把自研复杂度花在差异化上，而不是重造通用能力。

## 三、信息架构与界面布局

### 3.1 侧边栏形态（M1 主形态，默认宽 300px）

```
┌────────────────────────────┐
│ ● 今日编辑 12  待办 3      │ ← 状态条（F6）
├────────────────────────────┤
│ 📌 置顶 (2)                │ ← F5，M2
├────────────────────────────┤
│ 最近编辑            [≡排序]│ ← F1
│ 14:32 插件方案.md   #proj  │
│ 11:07 PG索引.md     #db    │
│ 昨天  周报.md       #work  │
├────────────────────────────┤
│ 标签                [频率]│ ← F2
│ #project  24  #db  17      │
│ #ai  12  #work  9   …      │
│ （点击→过滤上方最近编辑）   │
├────────────────────────────┤
│ ⌘ 日记 / 新建 / 搜索       │ ← F7，M2
└────────────────────────────┘
```

### 3.2 主区形态（M2，命令/ribbon 打开，不抢占新标签）

沿用报告 4.4 的驾驶舱布局：状态条 → 编辑脉冲 sparkline → 最近编辑×标签双栏 → 快捷入口。宽度 <700px 自动单列（F3）。

### 3.3 一目了然三规则

1. 状态条永远最上，**数字大、标签小**，一行读完系统状态；
2. 最近编辑默认 10 条内不滚动，等宽时间列对齐形成扫描节奏；
3. 标签带计数，点击即交叉过滤，**无二级页面**。

### 3.4 关键交互流

- 点标签 → 最近编辑列表过滤为该标签（再点共现标签 AND 收窄，Ctrl 排除）→ 点文件打开并高亮定位；
- 任意键入唤起搜索（F4）→ 键盘上下选择 → Enter 打开；
- 编辑任意笔记 → 事件驱动，对应行 300ms 内更新并短暂亮起琥珀色。

## 四、视觉设计（科技风 token 摘要）

完整推导见 [[Obsidian开发者工作台插件-开源调研分析报告#四、视觉设计方向：科技风 × 一目了然|分析报告第四节]]，此处只列执行结论：

| Token | Hex | 角色 |
|-------|-----|------|
| `deck` | `#0A0E1A` | 深空蓝底（非纯黑） |
| `panel` | `#111827` | 面板层 |
| `scan` | `#22D3EE` | 青：数据/导航/选中 |
| `pulse` | `#F59E0B` | 琥珀：时间/热度/注意 |
| `ok`/`alert` | `#34D399`/`#F87171` | 语义状态色 |
| `ink` | `#E2E8F0` | 主文字 |

- 数据一律等宽字体（`--font-monospace`）；UI 文字沿用宿主 `--font-interface`；
- 行式列表 + 分隔线组织信息，**不用同质圆角卡片网格**；
- 动效只编排一次（打开时数字滚动+sparkline 描线），其余只响应用户动作；尊重 `prefers-reduced-motion`，可一键关闭；
- 科技风是**可切换预设**，默认外观尊重用户主题（F8）。

## 五、技术架构

### 5.1 三层结构

```
┌─ 视图层 ────────────────────────────────┐
│ SidebarView(ItemView)  DeckView(ItemView)│
│ 共享渲染组件：状态条/文件行/标签面板      │
├─ 数据层 ────────────────────────────────┤
│ RecentIndex(mtime+打开序)  TagIndex(共现) │
│ PinStore(读核心Bookmarks)  StatsCache    │
├─ 集成层（全部可选、防御性探测）──────────┤
│ TagWrangler  Omnisearch  QuickAdd        │
│ obsidian-git  obsidian-tasks             │
└──────────────────────────────────────────┘
```

### 5.2 API 依赖（只走公开 API）

| 用途 | API | 备注 |
|------|-----|------|
| 最近编辑 | `vault.getMarkdownFiles()` + `stat.mtime`；`vault.on('modify'/'create'/'delete'/'rename')` | 核心路径 |
| 最近打开 | `workspace.getLastOpenFiles()` | 公开，仅 10 个，混排辅助 |
| 标签 | `getAllTags(cache)` + `metadataCache.on('changed')` 自建共现索引 | 不依赖 undocumented `getTags()` |
| 视图 | `registerView()` + `ItemView` + `getLeaf()` | 侧边栏/主区 |
| 收藏 | 核心 Bookmarks 插件 API（防御性探测） | 失效则隐藏导入入口 |
| 状态栏 | `addStatusBarItem()` | 轻量常驻入口（可选） |

### 5.3 刷新与性能策略（竞品 issue 教训直接转化为设计约束）

1. **事件驱动 + 防抖**（300ms），不做轮询；启动时全量建索引一次，之后增量（StartPage 范式）；
2. **细粒度局部更新**：只重渲染变化的行/标签，绝不整板刷新（Hearth #475 教训）；
3. **编辑态冻结**：用户正在工作台内交互（搜索/拖拽）时挂起刷新，结束后合并应用（Hearth #479 DOM 重建教训）；
4. **设置先行**：设置加载完成后再首渲，避免启动排序失效（Hearth #439 教训）；
5. 大库保护：列表 LIMIT、标签面板只显示 Top N + 展开、排除规则（默认不排除任何目录，用户可配）；
6. 卸载时注销全部事件与视图，无内存残留。

### 5.4 设置与错误处理

- 插件设置存 `data.json`（排序模式、条数、排除规则、集成开关）；视觉参数走 Style Settings `@settings`（styles.css 内声明 + onload 触发 `parse-style-settings`）；
- 主区视图**不替换新标签、不接管启动**（绕开 Homepage/Home tab 事故雷区），仅命令/ribbon 打开；
- 集成插件未安装/API 变更 → 对应卡片静默隐藏并在设置页说明，核心功能零影响；
- 任何失败显式报错（Notice），不裸 catch 吞错（Homepage #149 教训）。

## 六、非目标（明确不做）

- ❌ 通用卡片自由网格（Hearth 已做到极致，不正面竞争）；
- ❌ 替代 Dataview/Bases 查询引擎；
- ❌ 自建收藏数据孤岛（只读核心 Bookmarks）；
- ❌ 强制更改用户主题/接管启动与新标签；
- ❌ 部署、编排、网络请求类功能（纯本地，隐私零外发）；
- ❌ M1 阶段的移动端深度适配（保留宽度重排机制，M3 再 polish）。

## 七、实施阶段与验收

| 阶段 | 范围 | 验收标准（真实环境实测） |
|------|------|------------------------|
| **M1 核心闭环** | F1 最近编辑 + F2 标签共现 + F3 侧边栏 + F6 状态条 + F8 基础皮肤 | 在本库（数千笔记、60% 空占位）实测：冷启动索引 <1s；编辑笔记后侧栏 300ms 内更新；标签 AND/排除过滤正确；明暗主题均正常 |
| **M2 完整体验** | F3 主区视图 + F4 搜索 + F5 Pin + F7 launcher + F11/F12 + F8 预设切换 | 主区视图不抢占新标签；搜索键盘流全程不碰鼠标；Bookmarks 导入往返一致；窄窗单列重排 |
| **M3 开发者深化** | F9 任务写回 + F10 Git 卡 + 移动端 polish | 任务勾选回写原文件无损；obsidian-git 卸载/升级后工作台不崩；移动端可用 |

每阶段结束用真实 vault + 真实交互验证，不以 typecheck 代替功能验证。

## 八、开放决策点（含推荐默认项）

| 决策点 | 选项 | 推荐默认 | 理由 |
|--------|------|---------|------|
| 前端范式 | 原生 DOM+TS / Svelte / React | **原生 DOM+TS** | M1 规模小（两个视图+若干组件），官方 sample 范式、零构建负担、包体最小；若 M2 组件膨胀再评估 Svelte，届时单独出选型评估文档 |
| 插件名 | DevDeck / 开发驾驶舱 / 其他 | **DevDeck** | 短、可注册、契合驾驶舱概念 |
| 主区打开方式 | 命令+ribbon / 可选替换新标签 | **仅命令+ribbon** | 抢占新标签是竞品事故高发区，默认不做，后期可作显式开关 |
| 移动端 | M1 兼顾 / M3 polish | **M3 polish** | 宽度重排机制 M1 就内置，深度适配后置 |
| sparkline 与热力图 | 合并 / 分开 | **合并为 F6 编辑脉冲** | 避免信息重复，F12 只留数字统计 |

> [!note] 评审方式
> 以上默认项如无异议即按此执行；有异议直接指出对应行即可。技术选型若改选 Svelte/React，再按惯例出独立选型评估文档。
