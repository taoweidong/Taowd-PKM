# 知识库补全 100 篇技术文档规划

> [!摘要] 在 6 篇「从入门到精通」总览文档基础上，将知识点拆解为 **100 篇独立、详细介绍**的 md 学习文档，覆盖 AI 与大模型、前端与 Vue3、DevOps 与 Kubernetes、CI/CD 与 Jenkins、Python、Linux 六大方向，归档到对应目录结构，形成可检索、可复用的落地学习资料。

## 一、目标与拆分原则

- **目标**：每个知识点单独成篇，篇幅充实（详细原理 + 实践步骤 + 代码/命令示例 + 核心要点 + 资源），支撑「从入门到精通」的逐点落地。
- **拆分原则**：
  1. 按主题纵向切分，每篇聚焦**单一知识点**，避免多主题混杂。
  2. 遵循「基础概念 → 核心机制 → 实践落地 → 最佳实践 → 核心要点」的认知递进。
  3. 每篇可被总览文档与目录索引引用，内部用 wikilink 互联。
  4. 版本、日期等事实须有官方来源支撑，不编造。
- **总量**：100 篇，分布见下表。

## 五、执行阶段（多 agent 并行）

| 阶段 | 内容 | 执行方式 |
|------|------|---------|
| 0 规划 | 本规划文档、知识清单、归档路径 | 主 agent 产出 |
| 1 调研 | 6 主题各产出调研文件（最新版本、关键事实、官方来源），写入 `90-待整理与临时笔记/知识库补全100篇/调研/` | 6 个调研 agent 并行 |
| 2 写作 | 100 篇按主题并行写作，每篇读取对应主题调研文件 | 单 workflow 内分批限流（并发 6）并行写作 |
| 3 审校 | 按主题分组并行审校，修正事实与规范 | 6 个审校 agent 并行 |
| 4 集成 | 更新各目录索引、标签索引、最近更新、规划状态 | 主 agent 执行 |
| 5 汇总 | 质量复验与交付 | 主 agent 执行 |

## 六、质量红线

1. **不编造版本号/日期**：所有版本与时间须来自官方仓库或权威来源，无法核实时标注「以官方为准」。
2. **内部 wikilink 须存在**：`[[链接]]` 目标须在库中存在，避免悬空链接。
3. **外部链接用标准 Markdown**：`[文字](https://...)`。
4. **统一结构与标签**：每篇含 frontmatter（至少 `tags`）与完整章节。
5. **UTF-8 编码**：读写统一使用 UTF-8（无 BOM）。
6. **无占位残留**：不得出现「本页面内容待完善」等占位文字。
