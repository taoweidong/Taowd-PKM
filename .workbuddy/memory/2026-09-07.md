## 搭建「个人本地数据库 + 全栈工程师工作台」

**决策（用户四选一确认）**

| 维度 | 选择 |
|---|---|
| 形态 | Obsidian 增强（纯插件，不写代码） |
| 存储 | 纯 Markdown 文件为唯一数据源 |
| 场景 | 项目管理 + 任务/工单管理 |
| 助手命名 | 陶陶 |

**架构**：Markdown 笔记（数据层）→ `.base` 视图（视图层）→ 工程师工作台.md（展示层）

**新增文件**

| 文件 | 作用 |
|---|---|
| `50-项目记录/工程师工作台.md` | 仪表盘总入口，dataview 今日聚焦 + 嵌入两个 base |
| `50-项目记录/项目库.base` | 4 视图：全部项目 / 项目卡片 / 进行中 / 已交付 |
| `50-项目记录/工单库.base` | 5 视图：活跃工单 / 按项目 / 逾期 / 本周到期 / 已完成 |
| `95-模板/项目模板.md` | 项目笔记 Templater 模板 |
| `95-模板/工单模板.md` | 工单笔记 Templater 模板 |
| `50-项目记录/项目-全栈后台管理系统.md` | 示例项目（联调中） |
| `50-项目记录/工单/工单-*.md` | 3 个示例工单（含 1 个逾期样本） |

**数据模型约定**

- 项目笔记：`type: 项目` + `status` / `stack` / `backend_port` / `frontend_port` / `started` / `health` / `repo`
- 工单笔记：`type: 工单` + `project`(wikilink) / `status` / `priority`(P0-P3) / `category` / `due` / `created`
- Bases 与 Dataview 均用 `type` 字段筛选，保持单一判定依据

**验证**：两个 `.base` 文件 YAML 语法校验通过（Python 3.10 + pyyaml），视图与公式定义完整。

**踩坑预防**

- Obsidian Bases 中日期相减返回 Duration，必须先取 `.days` 再做数值运算
- base 的 view filter 里直接写 `date(due) < today()`，比引用 `formula.xxx == true` 更稳妥
- 索引文件 `95-模板.md` 原有 `[[通用模板]]` 是断链（实际文件名 `通用笔记模版`），已修正
