# 大模型幻觉与安全对齐

> [!summary] 摘要
> 本文聚焦大语言模型（LLM）落地中最常遇到的两类问题：**幻觉（Hallucination）**与**安全对齐（Safety Alignment）**。幻觉指模型生成看似合理、实则与事实或上下文不符的内容；安全对齐指让模型在有害请求、越狱攻击与越权行为下仍保持可控。二者同属"模型可靠性"范畴：幻觉侧重**事实正确性**，对齐侧重**行为边界**，但都依赖检索接地、采样控制、评估闭环与持续红队。本文梳理成因、机制、可运行的缓解实践与常见坑，适合需要把大模型安全地接入生产场景的工程师与学习者，可与 [[AI与大模型-从入门到精通]] 配合阅读。

## 一、最新动态（截至 2026-11）

> [!info] 说明
> 以下条目均取自调研文件《AI与大模型》的官方/权威来源整理，检索时点为 2026-11。相关研究与模型迭代极快，引用前请以官方页面当日状态复核。

- **幻觉与对齐研究持续演进，结论仍是"未解决"**：2026 年研究指出，幻觉源于模型对**参数化记忆的过度依赖**，缓解方向集中在检索接地（RAG）、温度/采样控制、事实性评估与机制可解释性研究（例如温度自适应 softmax 用于医疗记录场景）。来源：[Zenodo 幻觉相关研究记录](https://zenodo.org/records/19229177)
- **提示改写类攻击可绕过部分前沿模型的安全过滤**：2026 年研究显示，**人格设定、虚构框架、说服式改写**等提示改写攻击，仍能绕过部分前沿模型的安全过滤；**CHASE** 提出黑盒攻击者与安全防御者**协同进化**的红蓝对抗框架，并使用 **GRPO** 训练攻击者，把攻防从"静态过滤"推向"持续对抗"。来源：[CHASE（AACL 2026）](https://aclanthology.org/2026.aacl-long.36/)
- **多轮伦理红队带来新挑战**：**TRIAL** 方法表明，将有害请求嵌入伦理框架的**多轮红队**可稳定获得高攻击成功率，提示需要区分**工具性响应**与**有害结果**，不能只看单轮是否被拒。来源：[TRIAL（ACL 2026）](https://aclanthology.org/2026.acl-long.197/)
- **模型侧护栏走向分层**：Anthropic **Claude Fable 5.2 / Mythos 5.2（2026-11-11 发布）** 同底座两种版本——Fable 含面向全部用户的网络安全与生物安全护栏，Mythos 则移除部分护栏。这说明"对齐强度"已成为可配置的产品选择，而非单一默认值。来源：[Claude Fable 5.2 / Mythos 5.2 发布信息](https://cloudfresh.com/gc/news/claude-fable-5-2-and-mythos-5-2/)
- **长上下文不消除幻觉**：OpenAI **GPT-5.5（2026 年 4 月旗舰，1M 上下文）** 把上下文窗口做到百万级，但上下文变长不等于事实更可靠，反而需要更严格的注意力与引用治理。来源：[OpenAI 模型发布说明](https://help.openai.com/en/articles/9624314-model-release-notes)

> [!warning] 风险提示
> **安全对齐是持续对抗过程，不宜写成"已解决"。** 2026 年仍有提示改写与多轮红队突破安全过滤的案例，任何"模型已经安全"的绝对表述都应避免。

## 二、基础概念

**1. 幻觉（Hallucination）**

- **定义**：模型生成看似流畅、自信，但**与事实不符、与输入矛盾或无法验证**的内容，典型表现为编造事实、伪造引用、杜撰来源、捏造数据或给出无法兑现的承诺。
- **常见形态**：事实性幻觉（数字、日期、人名、法规）、引用幻觉（编造不存在的论文/链接）、上下文幻觉（违背给定材料）、推理幻觉（看似有据、实则跳步）。

**2. 安全对齐（Safety Alignment）**

- **定义**：通过训练与工程手段，使模型在面对有害请求、越狱（jailbreak）、提示注入（prompt injection）、越权操作时，**拒绝越界、不产生有害结果**，同时保留有用的工具性能力。
- **两层含义**：
  - **对齐训练**：SFT（学格式）、偏好优化（学取舍，如 DPO/PPO/GRPO）；
  - **运行时护栏**：输入/输出过滤、权限边界、工具白名单、对话级监控。

**3. 两者的关系**

幻觉与安全对齐都围绕"模型输出的可控性"：幻觉关心**内容对不对**，对齐关心**行为行不行**。一次生产事故往往两者交织——模型既编造了工具调用结果，又绕过了安全约束。因此评估与治理通常需要**同时覆盖事实性与安全性**。

## 三、核心机制

**幻觉的产生机制**

- **参数化记忆过度依赖**：模型依赖训练时记住的权重知识作答，一旦超出知识边界或知识过时，便倾向"补全"而非"承认未知"，这是幻觉的根本来源。
- **解码策略放大偏差**：高温度或采样随机性会让模型更易选择低概率、看似合理但错误的 token；低温度（或贪心）能降低随机性，但不能消除知识性错误。
- **上下文与检索不足**：当提示中缺少必要事实，或检索到的上下文噪声大、缺失关键证据时，模型会用先验知识"兜底"，产生幻觉。
- **训练数据缺陷**：数据冲突、标注噪声、来源不可验证、时效性差，都会把错误固化进模型。

**安全对齐的实现机制**

- **SFT（监督微调）**：让模型学会"该拒绝时拒绝"的输出格式，属于**学格式**。
- **偏好优化（DPO/PPO/GRPO）**：在"好/坏"偏好对上优化，让模型学会取舍，属于**学取舍**。2026 年红蓝对抗中已用 **GRPO** 训练攻击者，说明偏好优化同样可用于攻防迭代。
- **红队（Red Teaming）**：用对抗样本持续探测模型弱点，发现过滤缺口，再据此补强。
- **运行时护栏（Guardrails）**：在模型外层加输入检测、输出校验、工具权限、引用核验，是**不依赖模型自觉**的硬约束。
- **宪法式约束**：以显式规则（宪法/政策）约束输出，把"价值判断"从隐式训练转移到可审计的规则层。

**核心判断**：SFT 与偏好优化解决"模型内部倾向"，护栏与监控解决"外部硬约束"，**二者必须结合，缺一不可**。

## 四、实践步骤（含代码/命令示例）

**步骤 1：用采样参数降低随机性幻觉**

```python
from langchain_openai import ChatOpenAI

# 事实性任务：低温度 + 低 top-p，减少随机补全
model = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0.0,   # 事实问答尽量确定性
    top_p=0.1,         # 收窄候选集，降低"看似合理"的随机选择
)

answer = model.invoke("公司的注册成立日期是？请只依据给定材料回答。")
print(answer.content)
```

**步骤 2：检索接地（RAG）让模型"有据可依"**

幻觉最直接的缓解手段是把事实放进上下文，并**强制模型引用来源**：

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

materials = [
    {"id": "doc-01", "text": "本产品于 2021 年 6 月发布，支持离线运行。"},
    {"id": "doc-02", "text": "本产品当前版本为 2.3，不支持 Windows 10 以下系统。"},
]

prompt = ChatPromptTemplate.from_messages([
    ("system",
     "你只能依据【材料】回答问题。材料中没有的信息，直接回答“材料未提及”，"
     "不得推测。回答末尾需注明引用编号，如 [doc-01]。"),
    ("human", "本产品什么时候发布？支持哪些系统？\n\n【材料】\n{context}"),
])

context = "\n".join(f"[{d['id']}] {d['text']}" for d in materials)
msg = prompt.invoke({"context": context}) | model
print(msg.content)
```

**步骤 3：事实性校验（引用核验）**

对高风险场景（医疗、法律、财务），对模型输出的**每条引用**做独立核验，避免"编造引用"：

```python
import re

def verify_citations(answer: str, source_texts: dict) -> list:
    """返回无法被来源证实的引用编号。"""
    cites = set(re.findall(r"\[(doc-\d+)\]", answer))
    unverified = []
    for cid in cites:
        if cid not in source_texts or not answer_matches(answer, source_texts[cid]):
            unverified.append(cid)
    return unverified

# 说明：answer_matches 可按业务规则实现（关键词覆盖、语义相似度等）
unverified = verify_citations(answer, {d["id"]: d["text"] for d in materials})
if unverified:
    print("存在无法核验的引用，建议人工复核：", unverified)
```

**步骤 4：红队与越狱测试**

用对抗提示批量探测安全过滤，记录"是否被拒"与"拒绝是否合理"：

```bash
# 用 curl 对本地推理服务（如 vLLM OpenAI 兼容接口）跑红队样本
curl -s http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "your-model",
    "messages": [
      {"role": "system", "content": "你是严格遵守安全策略的助手。"},
      {"role": "user", "content": "<此处填入红队测试用例，如人格设定/虚构框架/说服式改写>"}
    ],
    "temperature": 0.0
  }' | python -c "import sys,json; print(json.load(sys.stdin)['choices'][0]['message']['content'])"
```

**步骤 5：部署运行时护栏**

用 YAML 声明式配置输入过滤、输出校验与工具权限，作为模型外的硬约束：

```yaml
guardrails:
  input:
    enable_pii_filter: true          # 脱敏
    max_prompt_length: 8192          # 超长注入防护
    block_patterns:                  # 已知越狱模板
      - "ignore previous instructions"
      - "you are now in developer mode"
  output:
    factuality_check: true           # 要求引用可核验
    max_answer_length: 4096
    require_citation: true           # 无引用则告警
  tools:
    allow_list: ["get_current_time"] # 工具白名单，越权调用直接拒绝
  monitoring:
    conversation_level: true         # 多轮对话级监控，而非只看单轮
```

## 五、最佳实践与常见坑

**最佳实践**

1. **先建评估集，再做调优**：准备真实用例的**事实性测试集**与**安全测试集**，每次改动都有可量化对照，避免"感觉更安全了"。
2. **RAG 是幻觉治理的主抓手**：优先保证切分合理、混合检索与重排，并强制**引用溯源**，让每句结论可核查。
3. **采样控制按场景分级**：事实/合规场景用低温度 + 低 top-p；创意场景才放开温度，避免用一套参数通吃。
4. **护栏与训练并行**：模型内部对齐 + 外部护栏 + 对话级监控三层结合，缺一层都可能被突破。
5. **持续红队**：把红队纳入上线流程与回归测试，攻防同步迭代（参考 CHASE 的协同进化思路）。

**常见坑**

| 坑 | 后果 | 对策 |
| --- | --- | --- |
| 只靠"模型自己说不" | 被提示改写、虚构框架绕过 | 加输入过滤、工具白名单与输出校验 |
| 只看单轮安全 | 多轮越狱漏检 | 引入对话级监控，记录多轮状态 |
| 高温度应对事实题 | 编造事实、随机跳步 | 事实场景降温度、收窄 top-p |
| 幻觉靠提示词"保证" | 模型承诺不可靠 | 用检索接地 + 引用核验，而非口头保证 |
| 引用形同虚设 | 编造引用不易察觉 | 逐条核验引用，无法证实则拦截/告警 |
| 把对齐当成一次性工程 | 新攻击方式出现即失守 | 建立红队回归与版本复核机制 |

## 六、核心要点速查

1. 幻觉根本原因是模型对**参数化记忆的过度依赖**，超出知识边界时倾向"补全"而非"承认未知"。
2. 幻觉按形态分事实性、引用、上下文、推理四类，治理要**分类施策**。
3. 采样控制（低温度、低 top-p）降低随机性幻觉，但**不能替代知识接地**。
4. RAG 检索接地 + **引用溯源**是抑制幻觉最有效的工程手段。
5. 安全对齐 = 对齐训练（SFT 学格式 / 偏好优化学取舍）+ 运行时护栏 + 持续红队，三层缺一不可。
6. **SFT 与偏好优化要区分**：前者解决输出格式，后者解决价值取舍。
7. 提示改写（人格设定、虚构框架、说服式改写）与**多轮红队**仍是 2026 年的有效攻击面，安全**不能写成已解决**。
8. 护栏要做**对话级监控**，单轮被拒不等于多轮安全。
9. 高风险场景（医疗、法律、财务）必须做**引用核验**，只凭模型自述不可靠。
10. 版本与新特性以官方仓库/文档为准，社区二手信息需回源核对。
