## 二、基础概念

大语言模型（Large Language Model，LLM）是一类以 **Transformer** 为骨干、在海量文本上预训练得到的生成式模型。理解它，先要掌握几个贯穿始终的基础概念。

- **Token 与词表（Vocabulary）**：模型并不直接理解汉字或单词，而是先把文本切分成 token，再映射为向量。一个 token 可能是一个词、一个字，也可能是一个子词片段；词表的大小决定了模型能表达的最小单元集合。
- **下一个 token 预测（Next-Token Prediction）**：LLM 的核心任务极其朴素——给定已出现的文本，预测下一个最可能的 token。生成时不断重复「预测 → 拼接 → 再预测」，即**自回归生成（autoregressive generation）**。模型的全部能力都源自这一目标下的大规模预训练与规模扩展（scaling laws）。
- **嵌入（Embedding）**：token 经嵌入层映射为固定维度的稠密向量，是模型理解语义的起点；向量之间的几何关系承载了语义相似性。
- **上下文窗口（Context Window）**：模型一次能处理的最大 token 数。窗口越长，可携带的历史信息越多，但显存与计算开销也随之上升；长上下文是 2026 年旗舰模型的普遍趋势（如 GPT-5.5 达 1M）。
- **温度与采样参数**：决定从概率分布中挑选 token 的方式，直接影响输出的稳定性与多样性，详见「核心机制」中的解码策略表。
- **预训练与对齐**：模型先经大规模预训练获得通用语言能力，再经监督微调（SFT）与偏好优化（如 DPO、GRPO）对齐到可使用、安全的行为，属于上层进阶主题。

## 三、核心机制

### 3.1 自注意力与多头注意力

**自注意力（Self-Attention）** 是 Transformer 的核心。输入经三组线性投影得到查询（Query）、键（Key）、值（Value），用 Q 与 K 计算相关性，再对 V 加权求和：

$$\text{Attention}(Q,K,V)=\text{softmax}\!\left(\frac{QK^{T}}{\sqrt{d_k}}\right)V$$

其中除以 $\sqrt{d_k}$ 用于缩放点积、稳定梯度。**多头注意力（Multi-Head Attention）** 在多个子空间并行计算注意力后拼接，使模型同时捕捉位置、语法、语义等不同维度的关系。

> [!note] 概念边界
> 2017 年的原始 Transformer 是 **encoder-decoder** 结构；当代 LLM 多为 **decoder-only**，并叠加 RoPE 位置编码、RMSNorm、SwiGLU 前馈层、GQA/MLA 注意力等改进。不要把原始结构直接等同于当今 LLM。

### 3.2 自回归生成与 KV Cache

生成是逐 token 的自回归过程：每一步把当前序列喂给模型，取输出分布中选中的 token，追加到序列后继续。**KV Cache** 缓存历史 token 的 Key/Value，避免每一步对全部历史重复计算，是自回归解码加速的关键，也是显存占用的主要来源——缓存随序列长度线性增长。vLLM 的 PagedAttention 以分页方式管理 KV cache，v0.34.0 更将**可扩展 KV cache 默认开启**，按实际空闲显存动态定容。

### 3.3 常用解码策略

| 策略 | 说明 | 适用场景 |
| --- | --- | --- |
| 贪心（Greedy） | 每步取概率最高的 token | 结果稳定、可复现的确定性任务 |
| 温度采样（Temperature） | 温度越低分布越尖锐、越保守；越高越随机 | 平衡多样性与质量 |
| Top-p（核采样） | 只在累积概率达 p 的候选集中采样 | 通用、控制随机性较精细 |
| Top-k | 只在概率最高的 k 个候选中采样 | 简单限制候选集 |

## 四、实践步骤（含代码/命令示例）

> [!example] 第 1 步：准备环境
> ```bash
> # 建议 Python 3.11+；vLLM 等引擎已收紧版本要求
> python --version
>
> # 创建并激活虚拟环境
> python -m venv .venv
> # Windows：
> .venv\Scripts\activate
> # Linux/macOS：
> # source .venv/bin/activate
>
> # 安装 LLM 基础依赖
> pip install "transformers>=5.0" torch
> ```

> [!example] 第 2 步：用 Transformers 观察下一个 token 预测
> ```python
> import torch
> from transformers import AutoTokenizer, AutoModelForCausalLM
>
> MODEL = "Qwen/Qwen2.5-0.5B-Instruct"  # 换用任意因果语言模型均可
>
> tokenizer = AutoTokenizer.from_pretrained(MODEL)
> model = AutoModelForCausalLM.from_pretrained(MODEL, device_map="auto")
>
> prompt = "大语言模型通过"
> inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
>
> # 1) 单次前向：看最后一个位置对「下一个 token」的预测分布
> with torch.no_grad():
>     next_logits = model(**inputs).logits[0][-1]
>
> top5 = next_logits.topk(5)
> print([(tokenizer.decode([i]), round(float(p), 4))
>        for i, p in zip(top5.indices, top5.values)])
>
> # 2) 自回归生成：逐 token 拼接出完整结果
> generated = model.generate(
>     **inputs,
>     max_new_tokens=64,
>     do_sample=True,
>     temperature=0.7,
>     top_p=0.9,
>     pad_token_id=tokenizer.eos_token_id,
> )
> print(tokenizer.decode(generated[0], skip_special_tokens=True))
> ```

> [!example] 第 3 步：用 vLLM 以 OpenAI 兼容接口起服务
> ```bash
> # 以 v0.34.0 的 vllm serve 作为标准启动方式
> vllm serve Qwen/Qwen2.5-0.5B-Instruct \
>   --tensor-parallel-size 1 \
>   --gpu-memory-utilization 0.9 \
>   --max-model-len 4096
> ```

> [!example] 第 4 步：调用服务并指定生成参数
> ```bash
> curl http://127.0.0.1:8000/v1/chat/completions \
>   -H "Content-Type: application/json" \
>   -d '{
>     "model": "Qwen/Qwen2.5-0.5B-Instruct",
>     "messages": [{"role": "user", "content": "用一句话解释什么是 KV Cache"}],
>     "temperature": 0.7,
>     "top_p": 0.9,
>     "max_tokens": 200
>   }'
> ```

> [!example] 生成参数配置示例（generation_config.yaml）
> ```yaml
> # 供服务端或客户端统一引用的生成参数
> temperature: 0.7        # 越低越保守
> top_p: 0.9              # 核采样阈值
> top_k: 50               # 候选集上限
> max_tokens: 512         # 单次生成上限
> presence_penalty: 0.0   # 避免重复话题
> frequency_penalty: 0.0  # 避免重复用词
> ```

## 五、最佳实践与常见坑

- **先建评估，再做调优**：先定义成功标准与测试集，再调温度、换模型；否则「感觉变好了」无法复现。
- **区分权重量化与 KV cache 量化**：压缩权重并不等于整体显存下降，KV cache 在生产批规模下可能占用 10–30GB，两条线必须分开优化。
- **参数搭配有讲究**：`temperature=0` 配合贪心最稳定；启用采样时建议同时设 `top_p` 或 `top_k` 限制候选，避免长尾噪声。
- **关注上下文窗口**：超长输入会放大显存与延迟，必要时做摘要、裁剪与分层组织，而不是一味「塞满窗口」。
- **锁定版本与依赖**：vLLM、Transformers 等存在破坏性变更（如 vLLM Model Runner V1 被移除），生产环境应锁定版本并回归验证。
- **区分概念边界**：不要把 2017 年 Transformer 结构当作当今 LLM；不要把提示工程当作模型能力的替代品，它与微调、RAG 互补。
- **可复现性**：需要可复现结果时用贪心解码并固定随机种子，避免采样带来的不确定性。

## 六、核心要点速查

1. LLM 的核心任务是**下一个 token 预测**，通过**自回归生成**逐 token 拼接出文本。
2. 自注意力用 Q/K/V 计算词与词之间的相关性，多头注意力并行捕捉多种语义关系。
3. 当代 LLM 多为 decoder-only，叠加 RoPE、RMSNorm、SwiGLU、GQA/MLA 等改进。
4. **KV Cache** 缓存历史键值、以显存换计算，是自回归解码加速与显存占用的关键抓手。
5. 解码策略：贪心稳定、温度调分布、Top-p/Top-k 限制候选，需按场景组合使用。
6. 上下文窗口决定可携带的历史信息量，越长开销越大。
7. 理解 LLM 的流水线是：token 化 → 向量化 → 自注意力层 → 采样/解码。
8. 版本号与新特性迭代极快，一律以**官方仓库/官方文档**当日状态为准。
