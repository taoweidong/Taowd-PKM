# 多模态大模型（视觉/语音）

> [!summary] 摘要
> 本文系统梳理多模态大模型（视觉/语音方向）的基本概念、核心机制与工程落地路径。多模态大模型指在文本之外，还能理解或生成图像、语音、视频的模型，当前正从「只看图」走向「图像 + 语音 + 视频」的理解与语音生成。内容覆盖 Qwen3-VL / Qwen3.5-Omni 等代表模型、视觉编码器与音频编码器、模态对齐、端到端语音对话等核心机制，并给出基于 Hugging Face Transformers、vLLM 与 OpenAI 兼容接口的可运行示例。适合已掌握 LLM 基础、希望把能力扩展到视觉与语音场景的开发者。体系位置见 [[AI与大模型-从入门到精通]]。

## 二、基础概念

**多模态大模型（Multimodal LLM）** 是指输入或输出不局限于文本 token，还能处理图像、语音、视频等模态的大模型。按能力侧重点可分为三类：

- **视觉语言模型（VLM）**：文本 + 图像理解，如图片问答、图表解析、文档 OCR、GUI 理解。
- **语音模型**：语音识别（ASR，语音 → 文本）、语音合成（TTS，文本 → 语音）、语音理解。
- **原生/端到端多模态模型**：在同一模型内完成跨模态的理解与生成，典型如语音到语音、图像 + 语音同时理解。

**关键术语**：

| 术语 | 含义 |
| --- | --- |
| 视觉编码器 | 将图像转为视觉 token（image tokens）的模块，常见如 ViT 变体 |
| 音频编码器 | 将波形转为音频 token 的模块，常见如 Whisper 系编码器 |
| 模态对齐 | 将不同模态的表征映射到统一的文本语义空间，使 LLM 可统一处理 |
| 多模态提示 | 在提示中同时携带文本与图片/音频输入，与纯文本提示有明显差异 |
| 端到端语音对话 | 语音进、语音出，中间不强制转成文本，延迟与自然度更优 |

## 三、核心机制

**统一架构：编码器 → 投影对齐 → LLM 主干 → 输出头。**

1. **模态编码**：图像经视觉编码器切成图像 token；语音经音频编码器（或分帧 + 编码）切成音频 token；文本按常规 tokenizer 处理。
2. **投影与对齐**：各模态 token 通过投影层映射到 LLM 的词向量空间，与文本 token 拼接后送入 Transformer。这是多模态能力的核心——**对齐质量直接决定跨模态推理水平**。
3. **统一自回归生成**：对齐后的多模态 token 序列进入与文本 LLM 相同的自回归解码，可生成文本、或预测语音/图像的输出 token。
4. **端到端语音**：VITA-1.5 等模型通过多阶段训练，先让模型理解视觉与语音，再在语音到语音任务中保持能力，避免「语音→文本→语音」多次转换带来的信息损失。

**与文本 LLM 的差异**：多模态的失败模式集中体现在 **OCR 长文本、复杂图表、密集截图** 等场景，提示词写法也需与纯文本分开设计。

## 四、实践步骤（含代码/命令示例）

### 4.1 环境准备

```bash
# 建议 Python 3.11+
python --version

# 安装多模态开发与推理依赖（按需取舍）
pip install "transformers>=5.20.0"
pip install "vllm>=0.34.0"
pip install torch torchaudio
pip install librosa soundfile
```

### 4.2 用 Transformers 做视觉问答

```python
from transformers import AutoProcessor, AutoModelForVision2Seq, AutoTokenizer

# 加载多模态模型与处理器（示例为 Qwen3-VL 系，具体模型名以官方模型卡为准）
processor = AutoProcessor.from_pretrained("Qwen/Qwen3-VL-7B-Instruct")
model = AutoModelForVision2Seq.from_pretrained(
    "Qwen/Qwen3-VL-7B-Instruct",
    dtype="auto",
    device_map="auto",
)

# 准备图文输入：图像需转为像素值，与文本提示一并编码
from PIL import Image

image = Image.open("chart.png")
messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "image": image},
            {"type": "text", "text": "请读取图中的柱状图，给出各季度的数值并简要分析趋势。"},
        ],
    }
]
text = processor.apply_chat_template(messages, add_generation_prompt=True)
inputs = processor(text=[text], images=[image], return_tensors="pt").to(model.device)

# 生成回答
output = model.generate(**inputs, max_new_tokens=512)
print(processor.batch_decode(output, skip_special_tokens=True)[0])
```

### 4.3 语音识别与语音输入

```python
from transformers import pipeline

# ASR：语音转文本
asr = pipeline("automatic-speech-recognition", model="openai/whisper-large-v3")
result = asr("speech.wav")
print(result["text"])

# 语音理解：将音频与文本问题一起送入多模态模型
from transformers import AutoProcessor, AutoModelForImageTextToText

processor = AutoProcessor.from_pretrained("Qwen/Qwen3-Omni-7B")
model = AutoModelForImageTextToText.from_pretrained(
    "Qwen/Qwen3-Omni-7B", dtype="auto", device_map="auto"
)

messages = [
    {
        "role": "user",
        "content": [
            {"type": "audio", "audio": "meeting.wav"},
            {"type": "text", "text": "总结这段录音的要点。"},
        ],
    }
]
text = processor.apply_chat_template(messages, add_generation_prompt=True)
inputs = processor(text=[text], audios=[{"path": "meeting.wav"}], return_tensors="pt").to(model.device)
out = model.generate(**inputs, max_new_tokens=512)
print(processor.batch_decode(out, skip_special_tokens=True)[0])
```

### 4.4 用 vLLM 部署多模态服务

```bash
# vLLM 提供 OpenAI 兼容接口，多模态模型同样适用
vllm serve Qwen/Qwen3-VL-7B-Instruct \
  --served-model-name qwen3-vl \
  --max-model-len 32768 \
  --dtype auto
```

调用方用标准 OpenAI 兼容接口发送图片（base64）即可：

```python
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8000/v1", api_key="EMPTY")

with open("chart.png", "rb") as f:
    b64 = __import__("base64").b64encode(f.read()).decode()

resp = client.chat.completions.create(
    model="qwen3-vl",
    messages=[
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "描述这张图。"},
                {"type": "image_url", "image_url": {"url": f"data:image/png;base64,{b64}"}},
            ],
        }
    ],
)
print(resp.choices[0].message.content)
```

### 4.5 端侧实时语音（llama.cpp）

```bash
# llama.cpp v0.8.0 提供实验性实时音频与 TTS 接口
llama-server -m qwen3-omni.gguf --host 0.0.0.0 --port 8080
# 语音输入走 /v1/realtime，语音合成走 POST /tts
```

## 五、最佳实践与常见坑

**最佳实践**

1. **先用最小模型验证链路**，确认图文/音频编码、提示模板、解码都正常，再上大模型或生产服务。
2. **多模态提示要具体到视觉细节**：明确说明关注区域、输出格式（如「列出表格数据」「按步骤描述」），避免笼统的「分析这张图」。
3. **评估与文本任务分开**：多模态评估需覆盖 OCR、图表、密集截图、长音频等失败高发场景，建立独立测试集与指标。
4. **服务层统一走 OpenAI 兼容接口**，用 vLLM 等引擎暴露服务，降低调用方迁移成本。
5. **控制上下文与成本**：视频、长音频会显著增加 token 与延迟，按需分段、裁剪或摘要。

**常见坑**

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 图片内容识别错乱 | 提示未指定关注点、分辨率被压缩 | 明确任务指令，保证图像分辨率，必要时放大裁剪 |
| 图表/密集截图漏读 | 视觉 token 容量不足 | 拆分子图逐块处理，或使用支持高分辨率的模型 |
| 长音频识别不准 | 未分段、音频编码器限制 | 先按句/按分钟切片再处理，必要时做 VAD |
| 语音延迟高 | 端到端模型逐步解码、未用流式 | 使用流式接口，或区分 ASR/TTS 拆分服务 |
| 显存不足（OOM） | 多模态 KV cache 与视觉/音频 token 膨胀 | 降低 `--max-model-len`、启用 KV cache 量化、量化权重 |
| 跨模态理解漂移 | 对齐训练不足或提示冲突 | 核对模型支持的模态与顺序，避免多模态与文本指令冲突 |

## 六、核心要点速查

1. 多模态大模型 = 文本 + 图像/语音/视频的理解与生成，按能力分 VLM、语音模型、端到端多模态三类。
2. 核心机制是「编码器 → 投影对齐 → LLM 主干 → 输出头」，**模态对齐质量决定跨模态能力**。
3. Qwen3-VL / Qwen3.5-Omni 覆盖文本、图像、音频、视频，最大 256K 序列、10 小时音频，是代表开源阵营。
4. VITA-1.5 以多阶段训练实现语音到语音的端到端多模态对话。
6. Transformers 已进入 v5 世代（最新 v5.22.2），多模态模型支持持续扩充。
7. 实践链路：Transformers 直接推理 → vLLM 部署 OpenAI 兼容服务 → llama.cpp 端侧实时语音。
8. 多模态提示要具体到视觉细节；评估需覆盖 OCR、图表、密集截图、长音频等高失败场景。
9. 多模态 token 与 KV cache 是显存和延迟的主要来源，务必与纯文本任务分开评估。
10. 版本号与新特性以官方仓库/模型卡为准，社区二手信息需回源核对。
